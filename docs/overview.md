# City Builder：工作流程和现状

这份说明讲两件事：一座城是怎么从地形一步步变成游戏里的方块的（原理），以及每一步现在做到了哪里（现状）。细节和取值依据在 [city-logic-design.md](city-logic-design.md)，代码约定在仓库根目录的 `CLAUDE.md`。写于 2026-11-23（0.0.4-alpha 之前）。

## 1. 一句话

City Builder 读 MTM_worldgen 的真实地形，先在大尺度上决定哪里有城、城有多大、城之间怎么连，再在城里铺路网、切地块、定功能、放建筑和铁路，最后在区块生成时把这些规划写成方块。城市布局接近 1:1（约 1 格对应现实 1 米），单体建筑按 Minecraft 的方块比例和实际通行空间适配。第一版只做亚洲风格（以京都为原型的日本城市）。

## 2. 原理

### 2.1 先规划，后放方块

城市不是在区块生成时"长"出来的，而是先有一份完整的规划（每座城长成后的样子），区块生成时只是按规划把这个区块里的那一部分写出来。所以：

- 区块按什么顺序生成都不影响结果，相邻区块的路、楼、铁路总能接上；
- 规划可以在后台线程提前做好（玩家附近的城先规划），区块生成时直接查。

### 2.2 从大到小分层

每一层只读上一层的结果和地形，按尺度从大到小：

| 层 | 做什么 | 尺度 | 代码 |
|---|---|---|---|
| L1 适宜度 | 每个 64 格网格点适不适合建城（平地、水、坡度） | 全世界 | `layer.SuitabilityLayer` |
| L1.5 文化区 | 亚洲/欧洲风格的大片区域（第一版只开亚洲） | 全世界 | `culture.CultureLayer` |
| L2 聚落 | 大都市、城市、镇、村的选址和分级 | 数十公里 | `settlement.SettlementLayer` |
| L3 城市范围 | 从市中心按代价洪泛出建成区和强度 | 城 | `extent.ExtentLayer` |
| L3.5 乡村用地 | 农田、林地 | 城外 | `extent` |
| L4 城际道路 | 城与城之间的路，带纵断面、隧道、桥、盘山 | 数十公里 | `road.RoadLayer` |
| L4b 城际铁路 | 只连大都市和城市，长隧道、高架，沿途镇设站 | 数十公里 | `rail.RailLayer` |
| L5 城市骨架 | 干道、古道、水渠、护城河、护岸、功能分区、主站和站前广场、城内铁路 | 城 | `street.StreetLayer` |
| L6 街道 | 支路、小巷、游步道，按 OSM 实测指标校准 | 城 | `street.StreetLayer` |
| L7 地块 | 沿街切地块，街区内部的后排地块和旗竿地 | 城 | `plot.TownPlots` |
| L7.5 功能 | 每条街的功能、学校医院公园寺社等设施用地、花街 | 城 | `function.FunctionLayer` |
| L8 建筑 | 每个地块上的建筑（种类、层数、占地、屋顶、材料） | 地块 | `building.BuildingLayer` |
| 区块层 | 把以上写成每一列的方块 | 16 × 16 | `chunk.ChunkLayer` 等 |

另外还有机场、港口、城外山上的寺社，各自一层，只划用地或铺地面。

### 2.3 哪些是纯函数，哪些存盘

- **L1、L1.5、L3–L8 是纯函数**：结果只由种子、坐标、配置和地形决定，算几次都一样，所以只缓存、不存盘。
- **L2（聚落）按规划块一次规划、存入存档**（`<维度目录>/citybuilder/citybuilder.db`，SQLite）。原因是聚落之间互相避让，纯函数做不到"不管先看哪里都一样"；存盘后，后规划的块总能看见先规划的，不会对不上。存档里的规划块不能删。
- **建筑布局按维度保存。** `CitySettings.forBuildingLayout` 读取规划库中的 `layout/building_scale`。新规划默认写入 9；有旧规划但缺少此标记时写入 1。已有标记的维度继续使用记录的布局，已生成区块也不会重铺。这项兼容机制覆盖建筑布局；其他生成算法在 alpha 期间仍可能改变区块衔接。
- **布局 9 的街边断面。** 并道处按局部路宽计算铺面、路肩挖填和地块进深。密集街区先留约两格平整前沿，再衔接边坡或挡墙；街坊尾部按可用面宽分地。种子 12345 的站前老街有 22 列草地方块原先高出人行道两格，逐列复测后均与人行道齐平。[设计与断面实测](city-logic-design.md#布局-9-的街边地形和地块)

### 2.4 让它够快

- **地形查询分两档**：平滑高度、地貌、湖面、河道这些便宜的查询（每点微秒级）用于规划；要算侵蚀的精细高度（每点约 2 ms，第一次进一个区域 0.5–1.5 s）只留给放东西的步骤。
- **远处的判断不触发水系计算**：大都市、城市、城际路线这类看几十公里外的判断，读去掉河湖的 `BroadTerrain`。
- **缓存按单位分**：区域尺度的层按区域缓存（LRU），城市尺度的层按城缓存；区块层按区块给城建索引（街道、铁路、整体生成的结构都按区块打包）。
- **后台规划**：`world.CityPlanner` 是一条低优先级线程，每 5 秒看一次玩家的位置，把 2.5 km 内的城和城际道路先规划好。区块线程遇到还没规划的城才会等。

### 2.5 尺寸和校准

- 尺寸按现实：住宅层高 3 格，干道 16 格宽，林荫大道 30 格，站台长度按城市等级 80–300 格。
- 路网用 OpenStreetMap 统计的真实城市指标校准（道路密度、路口类型、街区面积、朝向熵），建筑用京都 PLATEAU 的 51 万栋楼校准（层数分布、楼高与路宽、占地、屋顶、覆盖率）。调试工具会把生成结果和目标值并排打印。
- 不规则要"有原因"：时代层叠（古道 → 老城方格 → 铁路和现代改造）、地形和水、楼高跟路宽挂钩，不在结果上加随机扰动。

## 3. 游戏里怎么接上

- **地形**：只在 MTM_worldgen 的世界里建城（`terrain.Terrains.of(level)`）。两个兄弟 mod 都是软依赖：没装 MTM_worldgen 就不建城；MTR 只读车站数据，不写。
- **区块生成**：Mixin 挂在原版的生物群系装饰上。
  - 装饰之前（`world.CityChunks.pave`）：铺街道（路面、标线、人行道、桥、护岸、坡道），铺铁路（逐格铺的路基、地下箱体，以及整体生成的高架、车站、地下站和隧道），铺农田，把城里没有建筑的地块和高架下面铺成停车场。
  - 装饰之后：清掉长到路上的植物，放建筑（`world.CityBuildings`），再放公共建筑和公园。
  - 城镇用地里不雕洞穴峡谷，不开始原版结构。
- **出生点**：新世界出生在最近的城市中心。
- **城市地图**：按 K 打开。服务端在低优先级线程上画瓦片发给客户端，不下发种子。

## 4. 怎么验证

- **单元测试**（`gradlew :core:test`，约 6 分钟）：每个测试都在真实地形上新建一份规划，查几何、尺寸、相互避让、和实测的比例。
- **调试图**（`gradlew :core:cityMap -Players=<层>`）：每层一张图，再加一份统计。比如 `-Players=buildings` 会按圆环打印毛覆盖率、容积率，以及每环的土地都用在了哪里。
- **游戏内自动测试**（`autotest/`，`node run.mjs [--client]`）：自动启动开发服务器，经 TestKit 的 HTTP 接口生成区块、数方块、找特定的路/桥/车站；带客户端时自动截图（`docs/screens/`）。服务器日志里有新的报错就算失败。

## 5. 现状

"已完成"指已经接进游戏、在开发服务器上自动测试过；Forge 版只编译过，还没在游戏里跑过。

| 部分 | 状态 |
|---|---|
| L1–L3.5（适宜度、文化区、聚落、城市范围、乡村） | 已完成 |
| L4 城际道路 | 已完成：路面、挖填放坡、隧道、桥 |
| L4b 城际铁路 | 已完成：路基、桥、隧道，穿过沿途的镇和村；城外车站建筑还没有 |
| 高速线 | 只预留线位和站区，不建结构 |
| L5/L6 城市路网 | 已完成：干道、支路、小巷、游步道、桥、暗渠、坡道、台阶、护岸、站前广场 |
| 城内铁路（高架、地面） | 已完成：高架和地上车站由结构库整体生成，有多种高架和车站，桥墩避开道路（门型、倒 L 型） |
| 城内铁路（地下） | 已完成：地下站由结构库的明挖车站整体生成（站厅、站台、楼梯扶梯、出入口），深在地下的线段用箱形隧道；深埋站、盾构隧道、换乘站还没用 |
| L7 地块 | 已完成 |
| L7.5 功能 | 已完成用地划分；市役所、图书馆、医院、加油站、学校、诊所、交番、消防署、钱汤、各种公园有模型 |
| L8 建筑 | 普通建筑已放进城里（町家、住宅、商店、公寓、办公楼、工厂、仓库、便利店等）；地标（城、塔、PLATEAU 体素化建筑）还没接进来 |
| 本 mod 方块 | 路面和标线、窗、屋面、墙面、门、灯、店招、设备、地面分层块和斜面、地标用方块 |
| 城市的增长（发展值、逐步开发） | 未做；现在每座城一开始就是长成的样子 |
| MTR 联动 | 只读车站，不写线路数据；轨道由玩家铺 |
| 客户端车流 | 未做 |
| 欧洲风格 | 未做（默认关闭） |

### 5.1 已知问题和下一步

- **建筑密度偏低**：种子 12345 的城下町，从中心向外的毛覆盖率是 42/32/23/23/17%，京都是 57/51/44/39/34%；1 层 15.7%（京都 9%），3 层 9%（京都 18%）。剩下的差距多是结构性的（城址、武家地的大宅院、河、公园、功能分区外的插花地），以及町家和土藏最多两层。
- **高架**：高架段两端的桥台和车站的支撑有时落在路面上；斜向高架的护栏是按 90° 转出来的，从上面看有锯齿。
- **路网**：两条路从同一个路口以十几度分开时，中间会留一条细长的绿地（试过合并，改动面太大，没有采用）。
- **地下**：只用了明挖车站和箱形隧道；两条线的车站重叠时只建一个（换乘站没接），深的线段也还是箱形（没用盾构和深埋站）；车站在弯道上墙面有台阶。
- **Forge**：还没在游戏里跑过。
